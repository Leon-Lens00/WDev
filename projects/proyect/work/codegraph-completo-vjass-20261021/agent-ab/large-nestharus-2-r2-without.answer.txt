`codegraph_explore` is unavailable. Source shows two recycling paths:

- **Immediate:** `Timer.destroy` gets `ExpirationCode(this).timerId`. If registered and that group is **not currently expiring**, it calls `ExpirationCode.destroy()`, then directly calls `TimerPool.recycleTimer(timerId)` only if the pool count becomes zero ([script.j:733–742](Systems/TimerTools/script.j#L733)). The intermediate destructor calls `TimerPool.unregister`, which decrements the count ([script.j:436](Systems/TimerTools/script.j#L436), [script.j:189–207](Systems/TimerTools/script.j#L189)).

- **Deferred:** If registered and currently expiring, `destroy` calls `DestructionQueue.add(this)` ([script.j:736–738](Systems/TimerTools/script.j#L736)). `Handler.expire` evaluates callbacks, registers pending creations, then calls `DestructionQueue.clean`; that invokes each queued `ExpirationCode.destroy()`. The handler recycles only if the resulting count is zero ([script.j:545–570](Systems/TimerTools/script.j#L545), [script.j:700–715](Systems/TimerTools/script.j#L700)). Pending registrations can therefore prevent recycling.

The callback wiring is `handler = function thistype.expire`, passed to repeating `TimerStart` calls ([script.j:719–723](Systems/TimerTools/script.j#L719), [script.j:629](Systems/TimerTools/script.j#L629), [script.j:669](Systems/TimerTools/script.j#L669)).

Unregistered nodes are merely disabled; `CreationQueue.register` later destroys them ([script.j:753–754](Systems/TimerTools/script.j#L753), [script.j:520–530](Systems/TimerTools/script.j#L520)). Recycling pauses the underlying timer and pushes its ID onto the free list ([script.j:280–283](Systems/TimerTools/script.j#L280)).
